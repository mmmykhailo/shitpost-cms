# Nicknames for hidden senders

Nickname identity and admin behavior agreed on 2026-10-15. Implementation is pending final confirmation of the shared design. The subsequent [queue-preparation design](queue-preparation.md) moves attribution into queue preparation and automatically refreshes waiting posts after nickname changes.

## Identity and scope

Identifiable users keep their existing account-based nicknames and ID/@observed_username entry flow. Hidden senders receive a separate nickname keyed by the exact `senderUserName` stored in their forwarded origin. Matching preserves case, whitespace, and Unicode sequences; display sanitization must never alter the lookup key.

Every hidden sender with the same exact name shares its nickname. A changed name is a different key, and a name shared with an identifiable user does not connect their nicknames. Channel, chat, absent, and unknown origins retain their current publication behavior. See [the identity decision](adr/0003-match-hidden-sender-nicknames-by-exact-forwarded-name.md).

## Admin workflow

Extend `/authors` / Author names with selectable observed hidden-sender entries. Include names from existing queued posts at rollout and observe names from future forwards. Keep observed entries available after their posts leave the queue, and provide pagination so older names and nicknames remain manageable.

Clearly label hidden senders and explain that their nickname is shared by all hidden senders with the same exact forwarded name. Selecting an entry captures its exact stored name, then prompts for only the nickname; admins do not need to type a sender name or split two names containing spaces. Existing ID/@observed_username entry remains available for identifiable users.

Setting a nickname again replaces it. An explicit removal action restores fallback to the forwarded sender name. Use the existing nickname validation: trim and collapse ASCII whitespace, require 1–64 Unicode code points, and reject remaining forbidden control and bidirectional formatting characters. Empty input is invalid rather than a removal request. Retain existing private-chat admin authorization, prompt cancellation and expiration, callback protection, and audit behavior.

## Publication behavior

Resolve the current nickname when preparing a post in the queue channel. A change or removal updates untouched bot-generated bylines of matching waiting posts and applies to future posts. Preserve admin edits and intentional byline removal instead of restoring or replacing them. Waiting posts needing a refresh are ineligible for publication until it is complete. Already published output stays unchanged; active or uncertain publication attempts retain the byline captured in their publication contract. Publication delivers the prepared version without appending attribution again.

Preserve the original sender name in stored origins and snapshots. Renewal therefore keeps the same nickname lookup key and preserves intentional admin edits or removals. Keep existing inline/separate byline selection during initial preparation and Telegram length handling: a nickname that causes overflow follows the existing `needs_edit` path without automatic truncation.

## Implementation outline

1. Add persistent hidden-sender observation and nickname storage with exact string equality and an independent namespace. Seed observed hidden names from existing queued origins without rewriting queued content or account-based aliases.
2. Extend policy repository observation, listing, lookup, set, and removal behavior for hidden senders. Preserve audit records and persistence across restarts.
3. Allow hidden-user preparation policy to use the resolved nickname while keeping the original forwarded name as fallback. Reuse current publication-contract and operation safeguards; follow the prepared-output renewal design so copied posts do not acquire queue-channel forwarding attribution.
4. Extend Author names with hidden-sender selection, nickname entry, replacement, removal, and navigation to older entries. Keep raw names in stored prompt/callback state and sanitize only their displayed labels.
5. Update README and the existing implementation plan to replace the current statement that hidden users cannot receive nicknames.

## Verification

- Migration/backfill makes names from pre-existing queued posts selectable and preserves existing account-based nicknames.
- Set, replace, remove, and restart retain the expected hidden-name nickname state and audit trail.
- Identical hidden names share a nickname; renamed senders do not match; case, whitespace, and Unicode variants remain distinct; identifiable users with the same name remain separate.
- Admins can select names containing spaces, cancel or retry invalid input, and reach entries beyond the first page. Existing authorization and expired/stale callback protections still apply.
- Nickname changes affect untouched generated bylines in queued and future posts, preserve admin overrides, and leave active/uncertain publication contracts and published output with their captured bylines.
- Hidden-name nicknames work for text, captioned media, separate bylines, albums, and renewed sources. Existing nickname validation, overflow handling, and channel/chat policies remain intact.
